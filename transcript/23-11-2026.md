Does zalo web hook secret is secret token?

## 21:59 Claude

Yes. `ZALO_WEBHOOK_SECRET` is what Zalo's API calls the **secret token**, and it's separate from the bot token.

| | `ZALO_BOT_TOKEN` | `ZALO_WEBHOOK_SECRET` |
|---|---|---|
| Who creates it | Zalo gives it to you in Bot Creator | **You make it up** (8–256 characters, e.g. `openssl rand -hex 24`) |
| What it does | Lets the ERP call Zalo (send messages, set the webhook) | Lets the ERP check that a webhook call really comes from Zalo |
| Direction | ERP → Zalo | Zalo → ERP |

How the code uses it:
1. **At startup**, the ERP registers the webhook by calling `setWebhook` and passing your value as `secret_token` (`ZaloBot.registerWebhook`).
2. **On every message to the bot**, Zalo sends the same value back in the `X-Bot-Api-Secret-Token` header.
3. **The ERP compares the two** (`ZaloController.webhook`). If they don't match, it answers 401 and ignores the call, so nobody else can post fake link codes to `/zalo/webhook`.

If you ever register the webhook by hand in Bot Creator instead, put the same value in its secret-token field. If the two don't match, every message to the bot will be refused.

One caveat: these names come from Zalo's documentation, not from a real run, because the Zalo integration hasn't been tested against the live service yet. If linking fails with 401s, a header name that differs from the docs is the first thing to check.
