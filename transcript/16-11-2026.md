**Why it happened:** Tomcat refused the upload because it was over the 5 MB container limit, before your code ran. Spring Security then couldn't read the form's security (CSRF) token and refused the request as forbidden. Spring Boot's default error handler answers htmx requests with JSON, and htmx put that JSON on the page. Your existing "Photo too large" handler was never reached.

**What changed:**
- **Photo size:** the server's upload ceiling is now 20 MB and the app enforces the 5 MB rule itself, so a 5–20 MB photo re-shows the form with the message.
- **Instant check:** the browser now flags a photo over 5 MB as soon as it's chosen, so nothing is uploaded. The three photo inputs carry the limit, and the check is in `app.js`.
- **No more JSON pages:** a new `PageErrorController` replaces Spring Boot's error handler. Pages always get the normal error page; only `/api/` still gets JSON. Above 20 MB you get a "Photo too large" page; a form whose session ran out says "This page has expired, reload and try again" instead of a blank forbidden.
- **Errors after a button press:** a rule broken, a bad or missing value, or a conflicting edit now sends you back to the page you were on with the message there. This only uses the address the browser reports, never another site.
- **Someone else saved first:** the edit forms (shift, check-in, account details) now stay on screen with your input and a "reload and check their changes" message, instead of a 409 error page.
- **Report export:** a bad or future month, or a manager without a team, now goes back to the Team page with the reason. This matters because Firefox shows the month field as plain text.
- **Line breaks in text boxes:** a note that fits the 4,000-character box could still be rejected, because browsers send each line break as two characters. They're now counted as one.

Also: the language switch now uses the same back-to-page helper, so it keeps list filters too. Vietnamese translations are added for every new message.
